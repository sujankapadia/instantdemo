# Kokoro TTS

Research notes on Kokoro — a lightweight, high-quality open-source TTS model.

## Overview

Kokoro is an open-weight TTS model with 82 million parameters. Despite being tiny (~80MB quantized), it delivers quality comparable to much larger models and commercial APIs. It runs on CPU — no GPU required — and generates audio faster than real time (1.16s to produce 5.2s of audio in our testing on Apple Silicon).

**License**: Apache 2.0 — fully open, no restrictions. Can be deployed in production, personal projects, or anywhere.

## Background

- **Created by**: hexgrad (GitHub/HuggingFace)
- **Trained by**: @rzvzn (Discord)
- **Architecture**: Based on StyleTTS 2 (by Li et al.) combined with ISTFTNet. Decoder-only design — no diffusion or separate encoder, which keeps the parameter count low.
- **Training data**: A few hundred hours of permissive/public domain audio, Apache/MIT-licensed audio, and synthetic audio generated by commercial TTS models.
- **Text processing**: Uses `misaki`, a custom grapheme-to-phoneme (G2P) library that converts written text into phoneme sequences (pronunciation) before the model generates audio. English spelling is inconsistent ("read" can be /riːd/ or /rɛd/), so G2P is essential for correct pronunciation.
- **Name**: "Kokoro" is Japanese for "heart" or "spirit."

## Installation

```bash
pip install "kokoro>=0.9.4" soundfile
```

On Linux, also: `apt-get install espeak-ng`

No GPU drivers, no model downloads, no API keys. The model weights download automatically on first use.

## Usage

```python
from kokoro import KPipeline
import soundfile as sf

pipeline = KPipeline(lang_code='a')  # 'a' = American English

text = "Claude Code Analytics gives you a live view of all your running sessions."

for i, (gs, ps, audio) in enumerate(pipeline(text, voice='af_heart', speed=1)):
    sf.write(f'segment_{i}.wav', audio, 24000)
```

The generator yields chunks — for short narration segments (one sentence), it typically yields one chunk.

## Configuration

| Parameter | Values | Default | Notes |
|---|---|---|---|
| `lang_code` | `a` (US English), `b` (British), `e` (Spanish), `f` (French), `h` (Hindi), `i` (Italian), `j` (Japanese), `p` (Brazilian Portuguese), `z` (Mandarin) | — | Set on `KPipeline()` constructor |
| `voice` | 54 voices across 8 languages (see below) | — | String name or tensor (for voice mixing) |
| `speed` | Float | 1.0 | Higher = faster speech |
| `split_pattern` | Regex | `r'\n+'` | How to split text into chunks for generation |

## Performance

From our testing on Apple Silicon (M-series Mac, CPU mode):

| Metric | Value |
|---|---|
| Generation time | 1.16s for 5.2s of audio |
| Real-time factor | ~4.5x faster than real time |
| Model load time | ~2s (first call, includes download on first ever use) |
| Output format | WAV, 24kHz |
| Memory usage | Minimal (~200MB with model loaded) |

## Cost Comparison

| Provider | Cost | Quality | Speed | Local? |
|---|---|---|---|---|
| **Kokoro** | Free | Near-human (A grade voices) | ~1s/segment | Yes |
| **Piper** | Free | Robotic | ~1s/segment | Yes |
| **Google WaveNet** | Free tier (1M chars/mo) | Natural | ~2s/segment | No |
| **ElevenLabs** | ~$5/mo starter | Most natural | ~2s/segment | No |
| **Chatterbox** | Free | Beats ElevenLabs in blind tests | ~20s/segment (MPS) | Yes |

Kokoro hits a sweet spot: free, local, fast, and high quality. The main limitation is voice variety — the best voices are female, and male voices lag behind.

## Relevance to InstantDemo

Kokoro could replace both Piper (too robotic) and Google Cloud TTS (requires API setup) as the default TTS provider:

- No API keys or cloud setup needed
- Runs on any machine with Python 3.11+
- Quality is competitive with cloud providers
- Apache 2.0 license — no usage restrictions
- 1-2 second generation per segment — fast enough for iterative development

The main reason to keep ElevenLabs as an option: voice cloning. Kokoro doesn't support cloning from a sample — you're limited to the 54 built-in voices.
