# Kokoro pronunciation overrides: mechanics, detection, design

Authored 2026-05-14, updated 2026-05-15. Captures empirical
findings about how Kokoro's lexicon override mechanism behaves,
the deterministic detection + auto-resolution algorithm built on
top, and the precedence + data model for the
`pronunciations.json` feature.

> **M3 status (2026-06-10):** the product shipped the
> provider-UNIVERSAL slice instead — respelling entries
> (`{match, say}`) in `<project>/tts.json`, applied as a
> speech-text transform for every provider, verified by a
> listen-check preview in the GUI's Voice dialog. Pocket TTS
> (now the default provider) has no G2P/phoneme layer, so
> everything below that touches misaki's lexicon — IPA installs,
> miss detection, auto-resolution, the four-tier file precedence —
> remains DEFERRED, Kokoro-only design. See issue #54 for the
> rescope.

## TL;DR

- Kokoro uses **misaki** as its G2P frontend. Overrides are
  installed by direct mutation:
  `pipeline.g2p.lexicon.golds[word] = phonemes`.
- Overrides **win unconditionally** — they beat misaki's
  built-in lexicon, CMU dict, neural fallback, and rule-based
  G2P. Confirmed by test.
- The system has three precedence tiers: **project-level**
  `pronunciations.json` (highest) → **user-level**
  `~/.instantdemo/pronunciations.json` → **auto-resolved**
  entries (compound English splits via CMU dict) → Kokoro's
  default (no override).
- Detection is deterministic: a token is a "real miss" when
  neither it nor any of its plausible base forms (inflections,
  contractions, hyphen parts) are in misaki's `golds` ∪ CMU
  dict, OR it's an all-caps acronym (which Kokoro spells out
  regardless of dictionary presence).
- Auto-resolution is *conservative*: install only **high-
  confidence compound splits** (≥2 parts, each ≥4 chars, all
  parts in CMU dict). Single-part splits are real-word
  reinterpretations of acronyms and are rejected. Short parts
  produce nonsense splits ("Kokoro" → "koko" + "ro") and are
  rejected.
- No agent involvement, no LLM-generated IPA, no Phase 2
  prompt changes. The agent's job is unchanged; the renderer
  handles pronunciation overrides at TTS time.

Reference implementation pattern:
`<kokoro-say>/kokoro_say.py` (a separate local project) — the
two-layer system (lexicon + text_replacements) is the direct
template for InstantDemo. The InstantDemo design **adds**
deterministic detection + auto-resolution on top.

## The data model: `pronunciations.json`

```json
{
  "lexicon": {
    "instantdemo": "ˈɪnstənt dˈɛmoʊ",
    "Kokoro": "koʊˈkoʊɹoʊ",
    "ENEX": "ˈiːnɛks",
    "api": "ˌeɪpiːˈaɪ"
  },
  "text_replacements": {
    "K8s": "kubernetes",
    "NGINX": "engine X"
  }
}
```

### `lexicon`

Keys: single-token strings (hyphens OK; no spaces). Author them
in the natural canonical form.

Values: IPA phoneme strings. Spaces in values are syllable
separators, not key issues.

### `text_replacements`

Keys: regex-escaped source patterns, matched with `\b` word
boundaries.

Values: replacement strings written for TTS readability (plain
English that Kokoro G2P will handle), NOT phonemes.

Used for:
- Case-sensitive disambiguation (lowercase lexicon entry exists,
  uppercase form needs different handling)
- Multi-word inputs that need to collapse to a single lexicon
  token
- Symbol-pronunciation hints when needed

## Precedence and load order

Highest precedence to lowest:

1. **`<project>/pronunciations.json`** — user-curated,
   project-specific. Lives next to `intent.json`.
2. **`~/.instantdemo/pronunciations.json`** — user-curated, applies
   to all projects. Seed file (see below) lives here.
3. **`<project>/.instantdemo/pronunciations-auto.json`** —
   generated by the auto-resolver at render time. High-confidence
   compound splits only.
4. **Kokoro's default G2P** — applies to everything not covered
   above.

Merge rule: project keys win on conflict against user-level;
manual entries (1, 2) win over auto-resolved (3) on conflict.

## Detection algorithm

For each token in the narration (using
`pipeline.g2p(text)` for the tokenization that matches what
Kokoro will see):

```python
def is_real_miss(token_text: str, golds: dict, cmu_keys: set) -> bool:
    word = _clean(token_text)  # strip surrounding punctuation, lowercase

    # All-caps acronyms always get flagged, regardless of dict presence.
    # Kokoro spells out all-caps tokens letter-by-letter, bypassing
    # the lexicon. The user-level seed file is expected to provide
    # explicit pronunciations for common acronyms.
    if token_text.isupper() and 2 <= len(token_text) <= 6 and token_text.isalpha():
        return True

    if not word.replace("-", "").replace("'", "").isalpha():
        return False  # punctuation / numbers / mixed

    # Check the word itself + plausible base forms against both
    # misaki's lexicon and CMU dict.
    for base in _candidate_bases(word):
        if base in golds or base in cmu_keys:
            return False

    # Hyphenated compounds where all parts are known: fallback handles it.
    if "-" in word:
        parts = [p for p in word.split("-") if p]
        if parts and all(_is_known(p) for p in parts):
            return False

    return True
```

`_candidate_bases(word)` covers:
- Contractions: `'s`, `'re`, `'ve`, `'ll`, `'d`, `'m`, `n't`
- Plurals: `-s`, `-es`
- Past tense / gerund: `-ed`, `-ing` (with optional final `e`)

### Why the inflection filter matters

Naive detection ("not in `golds`") produces ~24 candidates per
8-segment narration, almost all false positives. Misaki's lexicon
stores root forms and uses morphological rules in the fallback for
inflections; `captures`, `runs`, `messages`, `here's` are all
correctly pronounced by Kokoro despite missing from `golds`.

After applying the inflection filter + CMU dict check:
- 8-segment narration produces **1-2 candidates** in practice
- All remaining candidates are genuinely novel words

### Why all-caps tokens need a bypass

Empirically observed: when a token is all-caps, Kokoro **post-
processes the phoneme string** by injecting stress marks
(emphasis behavior). For acronyms like `API`, `JSON`, `ENEX`,
this means Kokoro's default output is letter-by-letter spelling
("EE-EN-EE-EKS") regardless of whether the lowercase form is in
the lexicon.

So even if "enex" is in CMU dict (it is, surprisingly), the
all-caps input bypasses that. The all-caps detection ensures
these tokens still get flagged for the user's attention.

## Auto-resolution algorithm

For each detected candidate, attempt a high-confidence compound
split:

```python
def try_resolve(word: str, cmu: dict) -> str | None:
    parts = _split_compound(word.lower(), min_part_len=4)
    if parts is None or len(parts) < 2:
        return None  # single-part splits are not real compounds
    ipa_segments = [_arpa_to_ipa(cmu[p][0]) for p in parts]
    return " ".join(ipa_segments)
```

Constraints:
1. **At least 2 parts.** A single-part "split" means CMU dict
   has the whole word — but if that whole word was an acronym
   like `api`, CMU's pronunciation is the spoken-as-word form,
   which is wrong for the user's intent. Rejected.
2. **Each part ≥4 characters.** Prevents nonsense splits like
   `Kokoro → koko + ro` (both technically in CMU dict but
   semantically meaningless).
3. **All parts must be in CMU dict.** If split fails to resolve
   every part, return None and leave Kokoro's default in place.

Stress marks (`ˈ` for primary, `ˌ` for secondary) are placed
immediately before the stressed vowel within each part, matching
the kokoro-say convention. Compound parts joined with a space
character (which is fine inside the value; values can have
spaces, only keys cannot).

### ARPAbet → IPA table

Most ARPAbet phonemes map 1:1 to IPA. Two need stress-conditional
handling (the schwa vs. wedge distinction in English):

| ARPAbet | IPA | Notes |
|---|---|---|
| AA, AE, AO, AW, AY | ɑ, æ, ɔ, aʊ, aɪ | vowels |
| EH, EY | ɛ, eɪ | |
| IH, IY | ɪ, i | |
| OW, OY | oʊ, ɔɪ | |
| UH, UW | ʊ, u | |
| AH | ʌ (stressed) / ə (unstressed) | the wedge/schwa distinction |
| ER | ɝ (stressed) / ɚ (unstressed) | r-colored schwa |
| B, D, F, G, K, L, M, N, P, R, S, T, V, W, Y, Z | b, d, f, ɡ, k, l, m, n, p, ɹ, s, t, v, w, j, z | consonants |
| CH, DH, HH, JH, NG, SH, TH, ZH | tʃ, ð, h, dʒ, ŋ, ʃ, θ, ʒ | digraph consonants |

Full table lives in `pronunciations.py` constants.

## Renderer behavior

Per render invocation (before the segment loop in
`generate_audio_kokoro`):

```python
def install_pronunciations(pipeline, project_dir, segments):
    # 1. Load manual overrides from highest-precedence files
    manual = merge_overrides(
        load_or_empty(USER_DEFAULT),       # ~/.instantdemo/...
        load_or_empty(USER_OVERRIDES),     # ~/.instantdemo/pronunciations.json
        load_or_empty(project_overrides),  # <project>/pronunciations.json
    )

    # 2. Detect remaining candidates from actual narration
    text = " ".join(s.get("narration", "") for s in segments)
    misses = detect_misses(text, pipeline, cmu_keys, manual.lexicon)

    # 3. Auto-resolve what we can; log the rest
    auto = {}
    unresolved = []
    for word in misses:
        ipa = try_resolve(word, cmu)
        if ipa:
            auto[word] = ipa
        else:
            unresolved.append(word)

    # 4. Write auto-resolved entries to .instantdemo/pronunciations-auto.json
    #    for transparency / debugging.
    save_auto_resolved(project_dir, auto)

    # 5. Apply text_replacements to each segment's narration BEFORE TTS
    for seg in segments:
        seg["narration"] = apply_text_replacements(
            seg["narration"], manual.text_replacements
        )

    # 6. Install all overrides into pipeline.g2p.lexicon.golds.
    #    Include lowercase variants so case differences don't matter.
    golds = pipeline.g2p.lexicon.golds
    for word, phonemes in (manual.lexicon | auto).items():
        golds[word] = phonemes
        golds[word.lower()] = phonemes
        # Skip uppercase: all-caps tokens get mangled regardless;
        # text_replacements should normalize them first.

    # 7. Log unresolved misses so the user knows what's still
    #    on Kokoro's default.
    if unresolved:
        log("Words using Kokoro's default pronunciation:", unresolved)
        log("Add to pronunciations.json if you want explicit overrides.")
```

## File locations and the seed

- **`<project>/pronunciations.json`** — version-controllable with
  the project; shared by handing over the project dir.
- **`~/.instantdemo/pronunciations.json`** — per-user, applies
  to every project.
- **`<package>/data/pronunciations-seed.json`** — bundled with
  InstantDemo. Contains the kokoro-say acronym list (API, CLI,
  CSS, DNS, GPU, HTML, HTTP, HTTPS, JSON, JWT, K8s, LLM, NGINX,
  OAuth, SQL, SSH, SSL, TLS, URL, YAML + plurals). Loaded as
  the lowest-precedence manual layer; the user can override
  any of it.
- **`<project>/.instantdemo/pronunciations-auto.json`** —
  written by the renderer at render time. Documents what the
  auto-resolver installed for this project. Not user-edited;
  if the user wants to override an auto entry, they put it in
  the project or user-level file.

## Empirical findings (reference)

All test transcripts reproducible from
`scripts/explore/kokoro_lexicon_research.py` and
`scripts/explore/pronunciations_detect_resolve.py`.

### Finding 1 — Lexicon shape

```python
len(pipeline.g2p.lexicon.golds)  # 178,646 entries
# All keys lowercase, hyphens OK ("a-frame"), apostrophes OK ("a's"),
# zero keys contain spaces
```

### Finding 2 — Overrides win unconditionally

```python
golds["hello"] = "QQQ_HELLO_OVERRIDE"
pipeline.g2p("hello world")
# → ('QQQ_HELLO_OVERRIDE wˈɜɹld', ...)
```

`hello` is in CMU dict. Our override beats it. `api` was not in
`golds` at all (returned `None`) — Kokoro's default came from a
fallback layer.

### Finding 3 — Multi-word keys with spaces are silently ignored

Tokenizer splits on whitespace; keys with spaces are never
consulted. **Implication:** collapse multi-word terms via
`text_replacements` before TTS.

### Finding 4 — Case sensitivity with all-caps mangling

| Input token | Lowercase override `instantdemo`? | Output |
|---|---|---|
| `instantdemo` | ✓ matches | clean |
| `InstantDemo` | ✗ falls through to default G2P | default phonemes |
| `INSTANTDEMO` | ✓ matches, but Kokoro injects stress marks mid-string | **mangled** |

Mixed-case tokens fall through to default; all-caps tokens get
post-processed by Kokoro's emphasis layer regardless of override
match. **Implication:** install lowercase variants explicitly;
use `text_replacements` to normalize all-caps writings.

### Finding 5 — `pipeline.g2p(text)` is the test primitive

Returns `(combined_phoneme_string, [MToken...])` — verify
overrides fire without synthesizing audio. Used by `pronounce
test <word>`.

### Finding 6 — Empirical detection results on saved fixtures

| Fixture | Naive misses | After inflection filter | After CMU dict check |
|---|---|---|---|
| `dress-rehearsal-claude-code-analytics-scroll` (10 segs) | 15 | 8 | **1** (`instantdemo`) |
| `evernote-non-technical-fixed` (8 segs) | 9 | 5 | **1** (`Evernote`) |

Refinement reduced false-positive rate from ~94% (15/16) to 0%
on these fixtures.

### Finding 7 — Empirical resolution results

| Word | Compound split | Resolved IPA | Default phonemes | Verdict |
|---|---|---|---|---|
| `instantdemo` | `instant` + `demo` | `ˈɪnstənt dˈɛmoʊ` | `ˌɪnstəntdˈimO` | **fix** (default has wrong vowel + stress) |
| `Evernote` | `ever` + `note` | `ˈɛvɚ nˈoʊt` | `ˈɛvəɹnˌOt` | acceptable (default is plausible, resolved is more deterministic) |
| `Kokoro` | (no split; `koko`+`ro` rejected for ≥4 rule) | (unresolved) | `kəkˈɔɹO` | logged for manual entry |
| `Misaki` | (no split; `misa`+`ki` rejected) | (unresolved) | `mɪsəki` | logged for manual entry |
| `ENEX` | `enex` (single-part rejected) | (unresolved) | `ˌiˌɛnˌiˈɛks` (spelled out) | logged for manual entry |
| `API` | `api` (single-part rejected) | (unresolved) | `ˌApˌiˈI` (spelled out) | seed-file entry handles it |

## Known limitations

- **Truly opaque novel words** (Japanese, neologisms, made-up
  product names) cannot be auto-resolved. Falls through to
  Kokoro's default; user can override manually.
- **Acronym resolution conflict.** All-caps tokens whose
  lowercase form is in CMU dict (`enex`, `api`) would resolve
  to a real-word pronunciation that's wrong for the user's
  intent. Single-part rejection prevents this; user must
  provide their preferred pronunciation manually (or rely on
  the seed file).
- **Tokenizer artifacts.** Tokens with embedded punctuation
  (`demo-script.json`, `api/notes`) tokenize into surprising
  shapes. Detection mostly filters these out via the
  `isalpha` check; remaining edge cases would manifest as
  no-op log messages.

## Open questions (verified vs deferred)

- ✓ Does the override survive past CMU dict? **Yes**
  (Finding 2).
- ✓ Multi-word keys? **No, single-token only** (Finding 3).
- ✓ Case sensitivity? **Case-sensitive; lowercase variant
  needed; all-caps mangled** (Finding 4).
- ✓ What's Kokoro's fallback for words not in `golds`?
  **Some neural / rule-based G2P that may produce wrong output
  (e.g., `ˌɪnstəntdˈimO` for `instantdemo`).**
- ⚠ **Hyphenated unknown keys** (`claude-code-analytics`): the
  default lexicon has hyphenated keys (`a-frame`) so the
  mechanism is supported. Whether the tokenizer keeps an
  unknown hyphenated word as one token vs splitting it is
  untested. Worth a quick check when implementation begins.
- ⚠ **Does misaki accept ARPAbet values instead of IPA?**
  Untested. IPA works; whether ARPAbet would simplify the
  authoring surface (friendlier for cmudict-savvy users) is
  unknown. Defer until needed.
- ⚠ **Per-segment vs whole-text detection.** Current design
  detects from the union of all segment narrations. Per-segment
  would let the renderer warn users "this segment has an
  unresolved miss." Probably overkill for v1.
