# M0: storyboard.json — the canonical phase 2–5 contract

## Context

First milestone of PRODUCT_PLAN.md. Today phases 2–5 communicate via
markdown conventions parsed with regexes (segment headings, labeled
rows, fenced JSON) — implicit contracts that break when input
distributions shift (proven by the action-contract bug, #57).
`storyboard.json` becomes the single structured artifact phases write
and read; the `phaseN.md` files become **rendered views** generated by
runners (GUI markdown rendering + $EDITOR checkpoints keep working);
everything downstream (storyboard UI, notes, sections, versioned
takes) builds on this schema.

Settled: big-bang cutover on branch `feature/storyboard-contract`;
Phase 5 becomes a **deterministic transform** (no agent — user
confirmed); Phase 3 stays a separate phase; no frontend changes in
M0; `demo-script.json` / `render.py` / `segments.py` / state.json
`explore_findings` (and thus Phase4TriagePanel) untouched.

## Schema (new module `src/instantdemo/storyboard.py`, stdlib-only, actions.py style)

`.instantdemo/storyboard.json`:

```json
{
  "version": 1, "title": "...", "url": "...", "summary": "...",
  "created_at": "...", "updated_at": "...",
  "provenance": {"tone": "...", "audience": "...", "terminology": "", "intent_goal": "..."},
  "next_scene_seq": 9,
  "scenes": [{
    "id": "s2",                  // runner-assigned from next_scene_seq; stable; never reused
    "index": 2,                  // 1-based render order, recomputed on save
    "title": "...", "narration": "...",
    "action": "click",           // from actions.CANONICAL_ACTIONS (single source of truth)
    "selector": ["primary", "fallback"],   // ALWAYS arrays in-pipeline (also wait_for)
    "wait_for": ["..."], "pause_after_ms": 1200,
    "url"/"value"/"key"/"expression"/"pixels": "... (per action)",
    "target_hint": "...",        // Phase 2's high-level target line
    "notes": "...",
    "status": "planned|hypothesized|verified|warn|failed",
    "verification": {"status": "PASS|FAIL_SELECTOR|FAIL_NARRATIVE|WARN", "reason": "...", "suggestion": null},
    "revisions": [{"type": "selector|narration|wait_for|pause_after_ms", "from": "...", "to": "...", "reason": "...", "iteration": 1, "phase": 4}]
  }]
}
```

API: `load` (raises migration error if missing) / `save` (stamps
updated_at, recomputes index) / `new_document` / `add_scene` /
`normalize_candidates` / `extract_json_block` (lifted from
explore.py's JSON_BLOCK_RE) / `validate_storyboard(doc, stage=
"planned"|"hypothesized"|"verified")` / `to_demo_script(doc)` /
`render_phase2_view(doc, answers)` / `render_phase3_view(doc)` /
`render_phase4_view(doc, findings)`.

View format preserves what the GUI's MarkdownView custom renderers
expect: `### Segment {index} — {title}` headings + `- **Label:** value`
rows; phase2 view keeps the ANSWER block (tone/audience/terminology)
so `checkpoints.parse_answer_block` keeps working; phase4 view leads
with the findings JSON fenced block (keeps smoke assertion green).

## Per-file changes

- **`phases/__init__.py`**: add `run_structured_query(context, prompt,
  session_id, validate, phase_number)` — the generalized #57 pattern:
  run query → `extract_json_block` → validate → ONE corrective retry
  turn in-session → raise with problems. Used by narrate + gather.
- **`narrate.py`** (Phase 2): prompt unchanged except rewritten
  prompts/phase2.md output section (keep all narrative guidance +
  anti-patterns; agent may reason in prose but must END with one
  fenced JSON block: `{title, summary, scenes:[{title, narration,
  action, target_hint}]}`). Runner: build doc via `new_document` +
  `add_scene` (status `planned`), save storyboard, write phase2.md =
  rendered view with ANSWER block.
- **`gather.py`** (Phase 3): reads storyboard (not phase2.md); prompt
  embeds compact scenes JSON (id/index/title/narration/action/
  target_hint) + rewritten prompts/phase3.md (keep convention survey +
  lookup strategy; output = `{scenes:[{id, action, selector:[...],
  wait_for:[...], ...per-action fields, pause_after_ms, notes}]}` —
  **selector/wait_for always arrays, fallbacks graduate from Notes
  prose into the array**; no narration/title re-typing). Validator:
  returned ids == storyboard ids exactly once; merge by id over a
  field whitelist; `validate_storyboard(stage="hypothesized")`; set
  status; save; write phase3.md view.
- **`explore.py`** (Phase 4): segment count = `len(scenes)` (delete
  the `^###\s+Segment` regex); initial prompt embeds
  `render_phase3_view(doc)` (regenerated, guaranteeing consistency).
  Findings JSON contract UNCHANGED (state.json/GUI compat) **plus
  optional per-segment `"updates": {"wait_for": [...],
  "pause_after_ms": int}`** — closes the gap where Level-1
  timing/wait_for fixes lived only in Part-2 prose and would be lost
  to a deterministic Phase 5. Prompt rewrite: **Part 2 deleted**
  (response ends with the findings block; runner renders the human
  report) — kills the "two parts must agree" failure mode.
  Convergence loop unchanged. After loop: merge findings → scenes
  (selector_swapped → selector=[to] + revision; narration_revised →
  narration + revision; updates → apply + revision; status mapping
  PASS→verified / WARN→warn / FAIL_*→failed; verification field),
  merge BEFORE the BLOCKED raise; save storyboard; phase4.md =
  rendered view; phase4-diff.md + record_phase_metrics unchanged.
  Factor the merge as a pure function for unit testing.
- **`script.py`** (Phase 5): full rewrite, deterministic: load
  storyboard → `validate_storyboard(stage="verified")` →
  `to_demo_script` (single-element arrays project as bare strings —
  byte-shape matches today's demo-script.json convention; render.py's
  `_selector_candidates` already normalizes both) → final
  envelope + `actions.validate_segments` assertion → write
  demo-script.json → `state.record_phase_metrics(5, cost_usd=0.0,
  duration_ms=measured, num_turns=0, is_error=False)` + metrics
  append. No agent, no client guard. (Verified: record_phase_metrics
  takes arbitrary kwargs; GUI phase_complete SSE tolerates cost 0.)
- **`agent_client.py`**: remove `"phase5"` from PHASE_TOOLS + comment.
- **`prompts/phase5.md`**: delete.
- **Untouched**: actions.py, render.py, phases/render.py,
  analyze.py, server routes, checkpoints.py, intent.py, frontend.

## Migration stance

No auto-migration. `storyboard.load` raises: "storyboard.json not
found — this project predates the storyboard contract; re-run from
Phase 2." Legacy projects' existing artifacts/GUI/video flows keep
working; only running phases 3–5 demands the re-run. Document the
new editing reality in CLAUDE.md: phaseN.md are rendered views ($EDITOR
prose edits no longer feed forward; the phase2 ANSWER block still
does; power users edit storyboard.json directly).

   `tests/test_storyboard.py` → `pytest`. (low risk)
2. narrate.py + phase2.md prompt + `run_structured_query` + smoke.py
   updates → `python scripts/smoke.py` (~$0.04). (medium-high risk:
   first structured-output phase; retry + cheap iteration mitigate)
3. gather.py + phase3.md prompt → run phases [2,3] against the live
   Evernote fixture app; assert stage="hypothesized" clean; eyeball
   phase3.md view in GUI. (medium risk: id echo discipline)
4. Fixture conversion + explore.py + phase4.md prompt +
   rehearsal-smoke rewrite → `smoke_phase4_rehearsal.py` 5a, 5b, 5c

   (Part-2 removal + updates field), CHANGELOG. Commit per step;
   PR at the end.

## Verification plan (five layers; each step gated before the next)

**L1 — Unit (free, seconds, run at every step):** `pytest
tests/test_storyboard.py` — validators per stage (good + bad cases),
id assignment/uniqueness, normalize_candidates, extract_json_block,
the Phase 4 merge as a pure function (selector swap / narration
reground / updates / status mapping / out-of-range index), projection
round-trip (verified storyboard → demo-script passes
actions.validate_segments; 1-element arrays project as strings),
view snapshots (segment headings + labeled rows the GUI expects).

**L2 — Per-phase live gates (cheap, after each cutover step):**
- Step 2 gate: `scripts/smoke.py` (~$0.04, ~30s) — existing SSE +
  state assertions PLUS new ones: storyboard.json exists/valid/≥1
  scene, phase2.md view contains `### Segment 1`. Also eyeball the
  narration tone against a fixture phase2.md (JSON-output quality
  regression check).
- Step 3 gate: phases [2,3] against the live Evernote app (~$0.30) —
  `validate_storyboard(stage="hypothesized")` clean; selector/wait_for
  are arrays with fallbacks; phase3.md view renders in GUI EditorPane.
- Step 4 gate: `smoke_phase4_rehearsal.py` scenarios **5a, 5b, 5c**
  (~$0.3–0.5 each, vs claude-code-analytics on :8000). This is the
  strongest net we have: 5a proves happy-path merge + view + findings
  shape; 5b proves a deliberate selector break → FAIL_SELECTOR *or*
  swap with a `revisions` entry landing in the scene; 5c proves a
  planted overclaim → narration regrounded in the scene. New asserts
  tie findings ↔ scene state (every selector_swapped finding has a
  matching scene revision).
- Step 5 gate: unit projection tests + run phase [5] alone on the
  post-5a project — confirm demo-script.json validates, $0.00,
  <1s.

**L3 — End-to-end acceptance (the "M0 done" bar):** full 6-phase run
against the live Evernote app through the **GUI**:
- demo.mp4 renders; key frames verified via ffmpeg extraction (the
  established technique: layout frame, scrolled frame, detail frame)
- SSE/phase rail shows phase 5 at $0.00 and ~instant
- state.json `explore_findings`/`explore_overall` shape unchanged
  (Phase4TriagePanel contract): assert keys match a pre-M0 fixture's
- GUI artifact views for phases 2/3/4 render with segment headings,
  labeled rows, drift notices — eyeballed
- `scripts/smoke_segment_edit.py` ($0) — PATCH narration + audio
  re-render + delete still work on the produced demo-script.json
- One CLI run (`instantdemo phase 2 …` without --no-edit) to confirm
  the $EDITOR checkpoint opens the rendered view without error

**L4 — Legacy/migration behavior:** point phases 3/4/5 at a pre-M0
project (any existing fixture restore) → each fails fast with the
exact migration message, no partial writes; GUI still serves the old
project's artifacts/segments/video normally.

**L5 — User acceptance before merge (your verify-then-commit flow):**
you click through the GUI run, read the three rendered views, and
watch the final MP4; PR only after your sign-off.

Estimated total verification spend: ~$2.50–3.50 Claude usage, ~45 min
wall (dominated by the three rehearsal scenarios + two full runs).

## Key risks

- Phase 2 quality under JSON output → prose-before-block allowed,
  retry turn, compare smoke output tone against fixture phase2.md.
- Agent omits `updates` channel → worked example in prompt; view
  makes omissions visible.
- Findings index out of scene range → bounds-check + count
  cross-check in the retry path.
- Fixture hand-conversion errors → scenario 5a validates the fixture
  before 5b/5c mutate it.
